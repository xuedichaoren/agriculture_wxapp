# 湘农汇 · 命名规范

> 版本 v1.0 ｜ 2026-11-11 ｜ 适用于 `src/` 全部代码与云端 PostgreSQL。
> 目标：**前端 UI 工程师不用问后端字段含义，后端不用猜前端要什么**。

---

## 0. 三条铁律

1. **一个概念只用一个名字。** 商品归属人叫 `owner_id`，就叫到底；展示名统一 `author_name` / `nickname`，不允许同义不同名。
2. **分层不越界。** 页面只依赖 `src/api/`；页面里出现 `snake_case` 字段、或直接 `from('表名')`，一律视为 bug。
3. **禁缩写、禁拼音。** `cat` / `farm` / `pid` / `desc` / `img` 这类缩写全部废弃，见第 6 节。

---

## 1. 分层与命名职责

| 层 | 目录 | 命名风格 | 谁维护 |
|---|---|---|---|
| 页面 / 组件 | `src/pages`、`src/components` | camelCase 变量，kebab-case 文件名 | 前端 UI |
| 数据访问层（API） | `src/api/*.js` | `fetchXxx` / `createXxx` / `updateXxx` / `deleteXxx` / `toggleXxx` | 前端 + 后端共同评审 |
| 演示数据（Mock） | `src/mock/*.js` | 与真实表字段一一对应 | 前端 |
| 枚举字典 | `src/common/enums.js` | `UPPER_SNAKE` 常量 | 前端 + 后端 |
| 数据库 | PostgreSQL | `snake_case`，`模块_实体` | 后端 |

数据流：

```
页面 (camelCase VM)
   ↓  import * as api from '@/api/index.js'
API 层 (VM ↔ DB 行 转换，唯一允许出现 snake_case 的地方)
   ↓
Cloud SDK → PostgreSQL + RLS
```

## 2. 数据库命名

### 2.1 表名：`<模块>_<实体复数>`

| 模块前缀 | 含义 | 现有表 |
|---|---|---|
| `user_` | 账号、资料、关系 | `user_profiles`、`user_follows` |
| `community_` | 农友圈互动 | `community_posts`、`community_comments`、`community_likes` |
| `shop_` | 商品与交易（规划中） | `shop_products`、`shop_skus`、`shop_carts`、`shop_orders`、`shop_order_items`、`shop_addresses` |
| `farm_` | 农场、农事（规划中） | `farm_farms`、`farm_tasks`、`farm_records` |
| `marketing_` | 营销（规划中） | `marketing_coupons`、`marketing_user_coupons` |

规则：
- 全小写、下划线分隔、**复数**（`posts` 而不是 `post`）。
- 多对多关系表用「左_右的关系名」：`community_likes`、`user_follows`。
- 不用保留字做表名（`order` → `shop_orders`）。

### 2.2 字段名

| 类别 | 规则 | 示例 |
|---|---|---|
| 主键 | `id`（`bigint generated always as identity`） | `community_posts.id` |
| 归属人 | `owner_id text not null default auth.uid()`，**所有表统一**，RLS 靠它 | `community_posts.owner_id` |
| 外键 | `<实体单数>_id` | `post_id`、`product_id`、`farm_id`、`category_id`、`address_id` |
| 时间 | `created_at` / `updated_at` / `deleted_at`（软删） | 一律 `timestamptz not null default now()` |
| 布尔 | `is_xxx` | `is_default`、`is_checked` |
| 计数 | `xxx_count` | `like_count`、`stock_count` |
| 金额 | `price` / `xxx_amount`，`numeric(10,2)`，单位元，禁止 float | `price`、`freight_amount` |
| 图片 | 单图 `xxx_url`；多图 `images`（`jsonb` string[]） | `cover_url`、`community_posts.images` |
| 展示快照 | `author_name` / `author_avatar` / `author_role` | 发布时的署名快照 |
| 枚举 | 小写下划线，取值集中在 `src/common/enums.js` | `status = 'unshipped'` |

**关系表特例**：`user_follows` 用 `follower_id` / `following_id`（语义比 `user_id`/`target_user_id` 更清晰），其中 `follower_id` 就是归属人，RLS 写成 `follower_id = auth.uid()`。

### 2.3 索引、约束、注释

- 主键：`<表名>_pkey`
- 唯一：`<表名>_<字段1>_<字段2>_key`
- 普通索引：`idx_<表名>_<字段>`
- 外键：`<表名>_<字段>_fkey`，内容型外键默认 `ON DELETE CASCADE`
- RLS 策略：`<表名>_<动作>_<范围>`，如 `community_posts_read_all`、`community_posts_insert_own`
- **每张表、每个非自解释字段必须有 `COMMENT ON`**，数据字典由它兜底

### 2.4 枚举取值字典

| 字段 | 取值 |
|---|---|
| `community_posts.topic` | 我的菜园日记 / 今日收成 / 阳台种菜 / 助农在路上 |
| `user_profiles.user_role` | 农场主 / 农友 / 老主顾 |
| 订单 `status`（规划） | `unpaid` / `unshipped` / `shipping` / `unreceipted` / `done` / `refund` |

> 订单状态里 `shipping`（运输中）与 `unreceipted`（到自提点/派送中）是两个细粒度状态，
> 前端「待收货」页签同时包含两者，**不要合并成一个值**。

## 3. 前端命名

### 3.1 文件与目录

```
src/
  api/            数据访问层（唯一出口 index.js）
  mock/           演示数据（字段与表一致）
  common/         enums.js 字典 / utils.js 工具 / icons.js 图标 / avatar.js 兜底头像
  components/     kebab-case 组件：product-card.vue、price-tag.vue
  pages/<模块>/<页面>.vue
  store/index.js  本地状态（购物车、订单、地址、收藏）
```

- 页面按业务模块分目录：`product` / `order` / `post` / `profile` / `farm` / `message`；
- 一个页面一个 `.vue`，文件名用名词，不加 `Page` 后缀。

### 3.2 变量与函数

| 场景 | 规则 |
|---|---|
| 普通变量、参数 | camelCase：`productId`、`linkedProduct`、`followerCount` |
| 布尔 | `isXxx` / `hasXxx` / `canXxx`：`isLiked`、`isMine`、`isChecked` |
| 常量、枚举 | `UPPER_SNAKE`：`ORDER_STATUS`、`POST_TOPICS` |
| 读远程 | `fetchXxx()`：`fetchFeed`、`fetchFollowing` |
| 读本地 / 同步 | `getXxx()` / `findXxx()`：`findProduct`、`getStorage` |
| 写 | `createXxx` / `updateXxx` / `deleteXxx` / `toggleXxx`：`createPost`、`toggleLike` |
| 幂等建档 | `ensureXxx()`：`ensureProfile` |
| 事件处理 | `onXxx`：`onFollow`、`onScroll` |
| 计算属性 | 名词：`product`、`farmName`、`checkedItems` |

### 3.3 组件 props

- 声明用 camelCase（`originalPrice`），模板用 kebab-case（`:original-price`）。
- 布尔 prop 用 `is` 前缀或形容词，不要 `xxx-flag`。
- 组件不要透传数据库字段名，props 是「UI 语义」：`prod-img` 收 `src/emoji/bg`，不收 `cover_url`。

### 3.4 禁止清单

| 禁止 | 应写作 | 原因 |
|---|---|---|
| `cat` | `categoryId` | 缩写、含义模糊 |
| `farm`（商品上） | `farmId` | 区分「农场对象」与「外键」 |
| `origin` | `originalPrice` | `origin` 常指产地，歧义 |
| `sales` / `stock` | `salesCount` / `stockCount` | 数量必须带 `Count` |
| `desc` / `detail` | `summary` / `detailText` / `detailAddress` | 三者含义不同 |
| `img` | `coverUrl` | 统一 URL 命名 |
| `pid` | `productId` | 缩写 |
| `checked` | `isChecked` | 布尔前缀 |
| `uid` | `userId` / `authorId` | 明确是哪个用户 |
| `mine` | `isMine` | 布尔前缀 |
| 页面里 `'unpaid'` 等裸字符串 | `ORDER_STATUS.UNPAID` | 集中到 enums |
| 页面里 `from('表名')` | `api.xxx()` | 越过数据层 |
| 拼音、中文标识符 | 英文 | — |

## 4. 字段映射总表（DB ↔ VM）

| 数据库列 | 类型 | 前端 VM 字段 | 用途 |
|---|---|---|---|
| `owner_id` | text | `userId` / `authorId` | 用户唯一标识（= auth.uid()） |
| `nickname` | text | `nickname` | 用户昵称 |
| `avatar` | text | `avatar` | 头像 URL 或 emoji 占位 |
| `city` | text | `city` | 常驻地 |
| `user_role` | text | `userRole` | 身份 |
| `bio` | text | `bio` | 简介 |
| `author_name` | text | `authorName` | 内容署名快照 |
| `author_avatar` | text | `authorAvatar` | 内容头像快照 |
| `author_role` | text | `authorRole` | 内容身份快照 |
| `content` | text | `content` | 正文 |
| `product_id` | text | `productId` | 关联商品 |
| `images` | jsonb | `images` | 图片/占位数组 |
| `topic` | text | `topic` | 话题 |
| `post_id` | bigint | `postId` | 所属动态 |
| `follower_id` | text | — （仅 DB） | 关注发起人 |
| `following_id` | text | `userId` | 被关注人 |
| `created_at` | timestamptz | `createdAt` | 创建时间 |
| `updated_at` | timestamptz | `updatedAt` | 更新时间 |

转换只发生在 `src/api/*.js` 的 `toXxxVM()` 里；页面拿到的永远是 camelCase。
