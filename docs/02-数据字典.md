## 1. 总览

| 表名 | 说明 | RLS | 现有数据 |
|---|---|---|---|
| `user_profiles` | 用户资料（人） | 读公开 / 写本人 | — |
| `user_follows` | 关注关系 | 读公开 / 写本人 | — |

公共约定：

- 所有表都有 `owner_id text not null default auth.uid()`，代表「这一行的归属人」，RLS 判定的唯一依据。**前端永不上送该字段**。
- 时间统一 `timestamptz`，默认 `now()`，显示时前端本地化。
- 主键 `bigint generated always as identity`（`user_profiles` 例外，主键即用户 id）。

## 2. user_profiles（用户资料）

> 全站唯一的「人」信息来源。动态/评论里的 `author_*` 只是发布时快照。

| 列 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `owner_id` | text | 否 | `auth.uid()` | **PK**，等于登录用户 id |
| `nickname` | text | 是 | — | 昵称，缺省用 `湘农汇用户+后四位` |
| `avatar` | text | 是 | — | 头像：图片 URL 或 emoji 占位（如 `🧑‍🌾`） |
| `city` | text | 是 | — | 常驻地，如 `湖南 · 长沙` |
| `user_role` | text | 是 | — | `农场主` / `农友` / `老主顾` |
| `bio` | text | 是 | — | 一句话简介 |
| `created_at` | timestamptz | 否 | `now()` | 建档时间 |
| `updated_at` | timestamptz | 否 | `now()` | 更新时间 |

策略：`user_profiles_read_all`（SELECT true）、`user_profiles_insert_own`、`user_profiles_update_own`。无 DELETE（资料不物理删除）。

## 3. user_follows（关注关系）

> `follower` 关注 `following`。**不冗余昵称头像**，展示信息实时 join `user_profiles`，
> 避免用户改名后关注列表还显示旧名字。

| 列 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | bigint | 否 | identity | PK |
| `follower_id` | text | 否 | `auth.uid()` | 关注发起人（= 归属人） |
| `following_id` | text | 否 | — | 被关注人 |
| `created_at` | timestamptz | 否 | `now()` | 关注时间 |

约束：`UNIQUE (follower_id, following_id)` —— 重复关注返回 `23505`，接口层视为「已关注」。
索引：`idx_user_follows_follower_id`、`idx_user_follows_following_id`。
策略：`user_follows_read_all`、`user_follows_insert_own`、`user_follows_delete_own`（`follower_id = auth.uid()`，即只能取关自己发起的）。

## 4. community_posts（农友圈动态）

| 列 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | bigint | 否 | identity | PK |
| `owner_id` | text | 否 | `auth.uid()` | 发布者，RLS 归属 |
| `author_name` | text | 是 | — | 发布时昵称快照 |
| `author_avatar` | text | 是 | — | 发布时头像快照 |
| `author_role` | text | 是 | — | 发布时身份快照 |
| `content` | text | 否 | — | 正文，1–500 字（前端限制） |
| `product_id` | text | 是 | — | 关联商品 id（未来 `shop_products.id`），可空 |
| `images` | jsonb | 否 | `'[]'` | 图片数组，元素为 URL 或 emoji 占位 |
| `topic` | text | 是 | — | 话题名 |
| `created_at` | timestamptz | 否 | `now()` | 发布时间 |
| `updated_at` | timestamptz | 否 | `now()` | 更新时间 |

索引：`idx_community_posts_created_at`（`created_at DESC`）、`idx_community_posts_owner_id`（`owner_id, created_at DESC`）。
策略：`read_all` / `insert_own` / `update_own` / `delete_own`。

> 为什么快照：动态是内容，署名应保留发布当时的身份（如「农场主」），
> 用户后续改资料不影响历史内容展示。用户资料请以 `user_profiles` 为准。

| `created_at` | timestamptz | 否 | `now()` | 评论时间 |
| `updated_at` | timestamptz | 否 | `now()` | 更新时间 |

索引：`idx_community_comments_post_id`（`post_id, created_at`）。
策略：`read_all` / `insert_own` / `delete_own`。

## 6. community_likes（点赞）

| 列 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | bigint | 否 | identity | PK |
| `post_id` | bigint | 否 | — | FK → `community_posts.id`，`ON DELETE CASCADE` |
| `owner_id` | text | 否 | `auth.uid()` | 点赞者 |
| `created_at` | timestamptz | 否 | `now()` | 点赞时间 |

约束：`UNIQUE (post_id, owner_id)` —— 一人一条；重复点赞返回 `23505`，接口层返回「已点赞」。
索引：`idx_community_likes_post_id`。
策略：`read_all` / `insert_own` / `delete_own`。

> 点赞数不存冗余列，列表页用 `select post_id where post_id in (...)` 聚合，
> 保证计数永远与明细一致。数据量上万后再考虑加触发器维护 `like_count`。

## 7. RLS 一览

| 表 | SELECT | INSERT | UPDATE | DELETE |
|---|---|---|---|---|
| `user_profiles` | 所有人 | `owner_id = auth.uid()` | 同上 | 无 |
| `user_follows` | 所有人 | `follower_id = auth.uid()` | 无 | `follower_id = auth.uid()` |
| `community_posts` | 所有人 | `owner_id = auth.uid()` | 同上 | 同上 |
| `community_comments` | 所有人 | `owner_id = auth.uid()` | 无 | `owner_id = auth.uid()` |
| `community_likes` | 所有人 | `owner_id = auth.uid()` | 无 | `owner_id = auth.uid()` |

排错提示：操作报 `42501` 时，先确认该角色是否有 `GRANT`，再看策略；
两者是两道独立的门，缺任一都会表现为「策略没生效」。
