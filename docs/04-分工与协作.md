# 分工与协作

> 目标：前端 UI 与后端**同时开工**，不互相等待；接口一旦冻结，改动走流程。

---

## 1. 角色与边界

| 角色 | 负责 | 可以改 | 不要动 |
|---|---|---|---|
| 前端 UI 工程师 | 页面、样式、交互、组件 | `src/pages`、`src/components`、`src/store` | `src/api`、`src/mock`、数据库 |
| 前端数据层 | API 封装、VM 映射、mock 维护 | `src/api`、`src/mock`、`src/common/enums.js` | 页面样式、数据库策略 |
| 后端工程师 | 表结构、RLS、索引、真实接口 | 云端表、`docs/02-数据字典.md` | 页面、`src/api` 的 VM 形状 |

三条边界：

1. **页面不碰数据库**：`from('表名')` 只允许出现在 `src/api`。
2. **页面不碰 snake_case**：字段名在 API 层就转好。
3. **VM 形状是契约**：后端加字段可以，改名/删字段必须走变更流程。

---

## 2. 并行开发怎么跑

```
① 定契约          ② 前端并行            ③ 后端实现           ④ 切换
docs/03 写 VM  ─→  UI 用 src/mock 开发 ─→  按数据字典建表   ─→  只改 src/api/catalog.js
                   页面完全跑通            灌种子数据/RLS        页面零改动
```

- 前端不需要等后端：`src/mock/data.js` 的字段与 `shop_products` 一一对应，UI 直接用。
- 后端不需要等前端：按 `docs/02-数据字典.md` 第 8 节的字段草案建表即可。
- 切换成本 = 一个文件。以商品为例：

```js
// 现在（mock）
export { PRODUCTS } from '@/mock/index.js'

// 后端就绪后（只改这里，页面把同步调用改成 await）
export async function listProducts(categoryId = 'all') {
  const res = await fetch(`/api/products?categoryId=${categoryId}`)
  return res.json() // 返回 ProductVM[]，字段名不变
}
```

## 3. 字段变更 SOP

新增一个字段（例：动态增加「定位」）：

| 步 | 谁 | 做什么 |
|---|---|---|
| 1 | 后端 | `ALTER TABLE community_posts ADD COLUMN location text`，写 `COMMENT ON COLUMN` |
| 2 | 后端 | 更新 `docs/02-数据字典.md` |
| 3 | 前端数据层 | `POST_FIELDS` 加列 → `toPostVM` 输出 `location: row.location || ''` |
| 4 | 前端数据层 | 更新 `docs/03-接口契约.md` 的 `PostVM` |
| 5 | 前端 UI | 页面直接用 `post.location` |

铁律：**可选字段必须有默认值**，页面不写 `if (post.location !== undefined)`。
