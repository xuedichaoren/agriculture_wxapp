# 06 · 认养模块说明

认养（认养一块地）是独立于商城主链路的第二条业务线：用户认下一块地、选作物、按期收菜。
本文件说明**页面链路、数据流、状态字段**，以及后端接入时每个位置该换成什么接口。

---

## 一、页面链路

```
首页 / 农场主页 / 我的  ──►  认养大厅 adopt
                                 │  选地块（农场/面积筛选）
                                 ▼
                            地块详情 plot  ← 选作物、认养方式、周期，实时试算价格
                                 │  setAdoptDraft（草稿，不落盘）
                                 ▼
                            确认认养 adopt-confirm  → createAdoption 落库
                                 │  redirectTo
                                 ▼
                            认养结果 adopt-result（= 认养成功页）
                                 │
        ┌────────────────────────┴────────────────────────┐
        ▼                                                 ▼
   我的认养 my  ──►  认养详情 detail  ──►  配送记录 delivery
        │               │                 农事日历 calendar（按 code 过滤）
        │               ├──►  农事记录 record（补录一条）
        │               ├──►  云监工 monitor（机位 / 环境 / 派单 / 抓拍）
        │               └──►  收成 harvest（预估 / 已收 / 去向 / 记录）
        └──►  认养证书 certificate（保存图片 / 分享图片）
```

入口位置：

| 入口 | 位置 |
| --- | --- |
| 认养大厅 | `pages/tabbar/profile/profile`、农场主页 CTA、`pages/farm/adopt` 本身 |
| 我的认养 | 个人中心、认养大厅右上角 |
| 认养详情 | 我的认养列表项、农事日历里的地块与事项 |
| 配送记录 | 认养详情快捷入口、我的认养配送行 |
| 认养证书 | 我的认养「认养证书」按钮、认养详情快捷入口与分享菜单、认养结果页按钮 |
| 云监工 | 认养详情快捷入口、我的认养操作区、收成页右上角菜单 |
| 收成 | 认养详情快捷入口、我的认养操作区、收成页右上角菜单可回跳云监工 |

## 二、数据流

```
页面  →  api/index.js  →  api/adopt.js（认养单/地块/作物/套餐/周期/价格/进度）
                       →  api/adopt-plan.js（详情视图/配送计划/农事时间轴，纯函数）
                       →  api/adopt-live.js（云监工：机位/环境读数/抓拍/派单视图，纯函数）
                       →  api/adopt-harvest.js（收成：预估/已收/去向/记录，纯函数）
页面  →  store/index.js（认养单数组 adoptions + 下单草稿 adoptDraft）
                       →  store/adopt-extra.js（用户补录日志 + 配送标记 + 派单 + 收成去向）
```

### api/adopt.js（已有）

- `listPlots(filter)` / `plotFilters()` 大厅列表与筛选
- `findPlot` / `findCrop` / `planOf` / `cycleOf` 基础查询
- `plotView(plot)` 地块补农场、作物对象、满员标记
- `calcAdoptPrice({plot, planKey, cycleKey, cropIds})` 价格试算
- `progressOf` / `daysGone` / `daysLeft` / `statusText` / `cropsText` / `logsOf` 展示派生

### api/adopt-plan.js（本次新增）

| 函数 | 作用 |
| --- | --- |
| `adoptionView(a)` | 认养单 → 页面视图：地块、农场、套餐、周期、作物列表、进度与天数、`hasDelivery` |
| `deliveryPlanOf(a, marks)` | 生成逐次配送单（序号/日期/状态/运单号），日期以 `nextDelivery` 为锚点向两边推算 |
| `deliveryStats(list)` | 已签收 / 待配送 / 下一次配送 |
| `timelineOf(code, userLogs, year)` | 农场写的日志 + 用户补录，按日期倒序；`MM-DD` 自动补年份 |
| `shiftDate` / `spanDays` / `todayStr` | 日期工具 |

配送间隔：`freq = 1`（每周 1 次）→ 7 天；`freq = 2`（每周 2 次）→ 4 天。

### store/adopt-extra.js（本次新增）

| 方法 | 作用 |
| --- | --- |
| `addFarmLog(code, log)` / `userLogsOf(code)` | 用户补录的农事记录，按地块编号索引 |
| `marksOf(id)` / `markDelivery(id, no, status)` | 配送单标记：`received` 已签收 / `skipped` 已跳过 / `waiting` 待配送 |
| `sentCommandsOf(id)` / `sendPlotCommand(id, actionKey)` | 云监工派过的远程指令，按认养单 id → 动作 key 存时间戳（重派覆盖） |
| `harvestOpsOf(id)` / `addHarvestOp(id, op)` | 收成去向：作物 + 斤数 + 方式（`ship` 寄送 / `store` 存菜窖 / `points` 换积分） |

storage key：`nh_adopt_extra_v1`。不与主 store 的 `nh_state_v1` 混在一起，出问题只影响认养扩展数据。
四类数据共存一个 key：`logs` / `marks` / `commands` / `harvestOps`，都按认养单或地块编号索引，
新增字段时只需在 `load()` 的默认值里补一项，旧数据不会丢。

### api/adopt-cert.js（证书新增）

| 函数 | 作用 |
| --- | --- |
| `certNoOf(a)` | 证书编号 `XNH + 起始年月 + 单号后 6 位`，例 `XNH202609-920001` |
| `verifyCodeOf(a)` | 验真码，由 `id + startDate` 哈希出 8 位（字符集去掉 0/O/1/I），形如 `JTQR-NXUV` |
| `certificateOf(a)` | 认养单 → 证书视图：编号、验真码、认养人、农场、地块、作物、方式、期限、状态与水印文案 |
| `certSummaryOf(cert)` | 证书页顶部一句话（生效中 / 已完结 / 已作废） |

`CERT_STATUS` 把三种认养状态映射成证书表现：`growing` 生效中（有效）、`ended` 已完结（有效）、`cancelled` 已作废（无效 + 水印）。

编号与验真码必须是**稳定可复现**的纯函数：证书会被保存成图片、被打印、被报给客服，同一张认养单每次生成都要一致。

### common/cert-poster.js（证书新增）

小程序的证书图片只能靠 canvas 画，不能对 DOM 截图。这个文件把证书画成 750×1120 的逻辑画布（导出放大 2 倍）：

| 导出 | 作用 |
| --- | --- |
| `drawPoster(ctx, cert)` | 纯绘制：底纸、金色双框、标题、认养人、明细、落款、印章、验真码、失效水印 |
| `renderPoster(scope, cert)` | 在页面 `#certPoster` 的 2d 画布上渲染并 `canvasToTempFilePath` 出临时图片 |
| `savePoster(path)` | 保存到相册，未授权时弹窗引导去设置 |
| `sharePoster(path)` | 微信下走 `showShareImageMenu` 拉起「发送给朋友」 |

页面上的证书是 DOM 排版的展示件，图片版是第二份版式，改版时两处一起改（`certificate.vue` 的 `.paper` 与 `cert-poster.js` 的 `drawPoster`）。

### api/adopt-live.js（云监工新增）

演示版没有真实摄像头，所有读数用「认养单号 + 日期」做**稳定哈希**生成：同一条认养单每次进来看到的温湿度、
抓拍、在线人数都一样。稳定比随机重要——用户会截图发给家人，两次打开数字不一样就成了假数据。

| 函数 | 作用 |
| --- | --- |
| `CAMS` | 三个机位（地头全景 / 垄间特写 / 灌溉口） |
| `liveViewOf(a)` | 在线人数、码流、更新时间 |
| `envOf(a)` | 四项读数（空气温度、空气湿度、土壤含水、光照）与昨日对比、升降标记 |
| `soilOf(plot)` | 把 `黄壤土 · pH 6.4` 拆成土名与 pH |
| `snapshotsOf(a, n)` | 近 n 天每日抓拍（日期、时间、阶段文案、温度），演示版用渐变 + emoji 合成 |
| `trendSeriesOf(a, n)` | 近 n 天日均温与柱高百分比（14℃ 起算、30℃ 封顶） |
| `REMOTE_ACTIONS` | 四种远程派单：浇水 / 追肥 / 除虫 / 除草（含是否会收费） |
| `commandsOf(a, sent)` | 把本地已派时间戳合进动作定义，生成「已派单 · N 小时前」文案 |

### api/adopt-harvest.js（收成新增）

收成同样不落库：由「地块面积 / 作物亩产（`yieldText`）/ 认养天数」推导。斤数统一用**斤**，与 mock 对齐。

| 函数 | 作用 |
| --- | --- |
| `harvestViewOf(a, ops)` | 预期总产、已收、已安排、待收、百分比，按作物拆行；`canRedeem` 控制能否再安排 |
| `pickRecordsOf(a, ops)` | 收成记录：农场侧按 7 天一次模拟 + 用户安排的记录，按日期倒序 |
| `REDEEM_WAYS` | 三种去向：寄到家 / 存菜窖 / 换积分 |
| `pointsOfKg(kg)` | 斤数换积分（1 斤 = 20 积分） |

折算规则：

- 蔬菜按 20㎡ 一垄折算面积系数，夹在 0.5～2 之间；果树（`crop.days ≥ 120`）按棵，不折算。
- 已收 = 预期 × min(0.86, 已种天数 / 认养天数)：生长中最多算到 86%，留一点在地里，不把没采的算成已收。
- 待收 = 预期 − 已收 − 已安排；已安排为 0 时才能继续安排，避免超卖。
- 换积分会累加到 `store.user.points` 并 `persist()`。

## 三、认养单字段

```js
{
  id: 'AD20260920001',      // 认养编号，也用于证书编号
  plotId: 'ap1',            // 地块
  code: 'A-03',             // 地块编号（日志、配送都按它索引）
  farmId: 'f1',
  crops: ['c1', 'c3'],      // 作物 id 数组，最多 3 个
  planKey: 'full',          // 认养方式：full 全托 / care 代管 / self 自耕
  cycleKey: 'q1',           // 周期：q1 一季 / h1 半年 / y1 一年
  startDate, endDate,       // YYYY-MM-DD
  total: 477,               // 实付
  status: 'growing',        // growing 生长中 | ended 已结束 | cancelled 已退养
  freq: 2,                  // 每周配送次数，0 表示自提/代寄
  nextDelivery: '2026-11-18',
  deliveriesTotal: 12, deliveriesDone: 8,
  owner, phone, addressId, remark, createdAt
}
```

配送单不单独存库：由 `startDate + freq + nextDelivery + deliveriesTotal` 推导，用户签收/跳过只记标记。
后端接入后可改为独立 `adoption_delivery` 表，`deliveryPlanOf` 直接换成接口返回。

## 四、后端待补接口

| 位置 | 现状 | 后端接口 |
| --- | --- | --- |
| 大厅/地块 | mock `ADOPT_PLOTS` | `GET /adopt/plots?farmId&area` |
| 价格试算 | 前端纯计算 | `POST /adopt/quote`（避免前端改价） |
| 提交认养 | `createAdoption` 写本地 | `POST /adopt/orders` → 返回认养单 |
| 我的认养 | `store.adoptions` | `GET /adopt/orders?status` |
| 详情 | `adoptionView` | `GET /adopt/orders/:id` |
| 配送记录 | 前端推导 + 本地标记 | `GET /adopt/orders/:id/deliveries`、`POST .../deliveries/:no/receive` |
| 农事日志 | mock `ADOPT_LOGS` + 本地补录 | `GET /adopt/plots/:code/logs`、`POST /adopt/plots/:code/logs` |
| 退养 | 本地改状态 | `POST /adopt/orders/:id/cancel` |
| 证书 | `certificateOf` 前端派生编号与验真码 | `GET /adopt/orders/:id/certificate` → 服务端签发编号、验真码、签发时间 |
| 证书验真 | 前端不做校验 | `GET /adopt/certificate/verify?no=&code=` → 是否存在、状态是否有效 |
| 云监工画面 | 渐变 + emoji 合成占位 | `GET /adopt/plots/:code/cams`（机位与在线状态）、`GET /adopt/plots/:code/snapshots`（每日抓拍 url） |
| 环境读数 | 稳定哈希生成 | `GET /adopt/plots/:code/env`（分钟级读数，需带回昨日同期值算趋势） |
| 远程派单 | 本地时间戳 | `POST /adopt/plots/:code/commands` → 工单号、预计处理时间；处理完回写一条农事日志 |
| 收成预估 | 亩产 × 天数折算 | `GET /adopt/orders/:id/harvest` → 预估与实收斤数（实收以采收单为准） |
| 收成去向 | 本地记录 | `POST /adopt/orders/:id/redeem`（`{cropId, kg, way}`）→ 生成寄送单 / 代存单 / 积分流水 |

> 验真码目前是前端哈希，只能当作展示。接后端后必须由服务端签发并入库，否则「编号 + 验真码」不具备防伪能力。

## 五、已知限制（前端演示版）

1. 数据全在本地 storage，卸载小程序即丢失；`DEFAULT_ADOPTIONS` 是首次进入的演示数据。
2. 支付是假的：确认页点「确认支付」直接生成认养单，没有调起微信支付。
3. 照片是占位色块，不是真实相册图片（`uni.chooseImage` 未接）。
4. 证书导出依赖 canvas `type="2d"` 节点，只有微信小程序能保存 / 分享图片；H5 只展示，点了会提示到小程序里操作。
5. 配送单状态由日期与标记推定，没有物流轨迹（运单号是拼出来的）。
6. 云监工画面是渐变 + emoji 合成的占位，**没有真实视频流**；环境读数是稳定哈希，不来自传感器。
7. 远程派单只在本机记录时间戳，农场端没有任何接收方；刷新后按钮停在「已派单」状态。
8. 收成预估按亩产线性折算，与真实采收量无对应关系；兑换记录只落本地，换积分会直接改本地积分。
