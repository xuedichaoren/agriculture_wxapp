# 07 · 识图诊断与专家问诊

本模块解决农户「我的作物出了什么问题、该怎么办」的需求，拆成两条互相打通的链路：

```
拍照 / 选图  ──►  识植物  ──►  判病害（含长势）  ──►  给方案  ──►  有疑问转专家
   scan.vue      identifyPlant    diagnose          result.vue    expert/ask
```

识图能覆盖大部分常见情况；识图拿不准、或情况复杂时，一键把诊断结论预填进提问框，转给真人农艺师。

## 二、识图诊断

### 2.0 第一层：先认清楚是什么作物

#### 为什么必须单独一层

早期版本把「认作物」和「判病害」塞进同一个 HSV 颜色向量里猜，
用「绿色占比 + 边缘密度」比距离。这条路线**在数学上就不成立**：

- 健康叶片的颜色向量高度相似（绿色为主，黄/褐/白/黑都接近 0）；
- 茄子、番茄、辣椒、草莓的健康叶片在这个空间里几乎重合；
- 所以「茄子识别成草莓」不是参数没调好，而是特征维度里**根本没有能区分物种的信息**。

现在把物种识别彻底拆出去，交给专门做这件事的服务（**Pl@ntNet** / **百度智能云**），
本小程序的 10 种作物只是其中的一个白名单子集。

#### 三种服务模式（`api/plant-id.js` 的 `identifyConfig.provider`）

| provider | 适用 | 说明 |
| --- | --- | --- |
| `endpoint` | **上线推荐** | 自建代理，POST multipart 字段 `file`，返回 `{ candidates: [...] }`。API key 放服务端，小程序包里不出现 |
| `plantnet` | 本地调试 / 小流量 | 直连 Pl@ntNet，**key 会被扒包**，别用在正式版 |
| `baidu` | 国内备选 | 直连百度植物识别，同样建议改走代理换 token |
| `local` | 默认 / 未配置 | 不联网、**不猜物种**，只返回候选让用户点一下 |

#### 服务选型依据

| 服务 | 能力 | 成本 | 结论 |
| --- | --- | --- | --- |
| **Pl@ntNet** | 87,000+ 物种，支持 `organs`（叶/花/果/整株/树皮），50+ 语言俗名 | 免费 500 次/天，**允许商用**，超出需 Pro | 首选。对「带花带果」的图最准 |
| **百度智能云 植物识别** | 返回中文俗名，国内网络直连、备案容易 | 个人实名赠 1 万次（365 天），之后 0.003 元/次起 | 国内兜底。中文名反而更好映射 |
| 自训 TFLite 物种模型 | 只能覆盖训过的作物 | 要标注数据 + 训练 | 不划算，10 种作物用现成 API 更省 |

#### 配置步骤（Pl@ntNet）

1. 到 `my.plantnet.org` 注册，创建项目拿 API Key（免费额度 500 次/天）；
2. 小程序启动时配置：

```js
import { setIdentifyConfig } from '@/api/plant-id.js'

setIdentifyConfig({
  provider: 'plantnet',
  plantnetProject: 'crops',   // 限定作物，比 all 准
  plantnetKey: '你的key',
  minConfidence: 0.35,        // 低于此值转「请你确认」
  minGap: 0.12                // Top1 与 Top2 差太小时也转确认
})
```

3. 上线前改成走代理：

```js
setIdentifyConfig({ provider: 'endpoint', endpoint: 'https://your-host/identify-plant' })
```

代理侧收到图片后转发给 Pl@ntNet / 百度，把 key 留在服务端。

微信小程序后台需要把 `my-api.plantnet.org`、`aip.baidubce.com` 加进 request / uploadFile 合法域名；
本地调试可在开发者工具里勾「不校验合法域名」。

#### 中文/拉丁名 → 本地作物

`SPECIES_MAP` 负责收敛，覆盖 10 种作物的常见学名与中文别称：

| 作物 | 学名（节选） | 中文别称 |
| --- | --- | --- |
| `tomato` | Solanum lycopersicum | 番茄、西红柿 |
| `pepper` | Capsicum annuum | 辣椒、甜椒、青椒 |
| `cucumber` | Cucumis sativus | 黄瓜、青瓜 |
| `eggplant` | Solanum melongena | 茄子 |
| `cabbage` | Brassica oleracea / pekinensis | 白菜、大白菜、甘蓝 |
| `rice` | Oryza sativa | 水稻、稻 |
| `citrus` | Citrus reticulata / sinensis | 柑橘、橘子、脐橙 |
| `strawberry` | Fragaria × ananassa | 草莓 |
| `corn` | Zea mays | 玉米 |
| `bean` | Phaseolus vulgaris / Vigna | 豆角、菜豆、豇豆、大豆 |

归一化会去掉作者名（`L.`）、变种标记（`var.` / `subsp.`）、`×` 杂交符与标点，
先精确匹配、再包含匹配（「番茄果实」→ 番茄）。命中不了就返回空，走「未收录」分支，**不瞎猜**。

自测：24 个用例全部通过，`Solanum melongena L.` → `eggplant`（不再是草莓）。

#### 认不准时怎么办：转「请你确认」

| 条件 | 处理 |
| --- | --- |
| 置信度 < `minConfidence` | 列出候选，让用户点选 |
| Top1 与 Top2 差值 < `minGap` | 同上，并提示「两个分数很接近」 |
| 识别结果不在 10 种作物内 | 提示「不在支持范围内」，可转专家 |
| 服务超时 / 没配服务 | `local` 模式，列出常见作物让用户点 |
| 最终仍未确认 | 病害判定不执行，只做长势分析 |

**宁可不给结论，也不给错结论**——农户按错病名打错药，代价比「多问一句」大得多。

#### 拍摄部位直接影响准确率（重要）

`ORGAN_TYPES` 六个部位，对应 Pl@ntNet 的 `organs` 参数：

| 部位 | organs 值 | 拍摄要点 |
| --- | --- | --- |
| 自动 | `auto` | 整株入镜，带花或带果最准 |
| 叶片 | `leaf` | 叶片占画面 70%，避开强反光 |
| 花 | `flower` | **最好认的部位**，一朵就够 |
| 果实 | `fruit` | 带果柄一起拍，能区分近缘种 |
| 整株 | `habit` | 退后拍全株形态，含生长方式 |
| 茎/枝 | `bark` | 木本拍枝干皮孔与纹理 |

现实情况：**茄科（番茄/茄子/辣椒）在幼苗期只拍叶片，人也难分**，这是物种本身的视觉相似性决定的。
所以引导用户拍花或拍果，比在算法上死磕叶片更有效。`PLANT_HINT` 里给每种作物写了辨识要点，
选完作物后在页面上直接显示。

### 2.1 两档识别，接口一致

| 档位 | 触发条件 | 能力 | 稳定性 |
|---|---|---|---|
| **端侧特征**（默认） | `diagnoseConfig.endpoint` 为空 | 离屏 canvas 采样 → HSV 分类 → 与病害知识库做皮尔逊相关匹配（**只判病害/长势，不再用于认作物**） | 完全不依赖网络，同图出同结果 |
| **服务端模型** | 配了 `endpoint` 且返回置信度 ≥ `minModelConfidence` | 调用 TFLite 模型服务，返回 PlantVillage 38 类 | 准确率高，需要自建服务 |

两档走同一个 `diagnose()` 出口，返回同一个结构，页面完全不用改。配了模型但置信度不够时，**自动回落**端侧结果，不会把低置信度的模型结论抛给农户。

### 2.2 端侧特征算法（`common/image-feature.js`）

小程序跑不了 TFLite，所以端侧不训练模型，而是提取**可解释的、和病害强相关的颜色特征**：

1. `uni.createOffscreenCanvas` 把图片画到 48×48 的离屏画布；
2. 逐像素做 HSV 分类，统计五类占比：

   | 特征 | 判定区间（HSV） | 对应病害信号 |
   |---|---|---|
   | `yellow` | H 35–70，S > 0.3，V > 0.4 | 黄化、褪绿、病毒病、缺素 |
   | `brown` | H 10–35，S > 0.25 | 褐斑、轮纹斑、锈病 |
   | `white` | S < 0.15，V > 0.75 | 白粉、霉层、白化 |
   | `dark` | V < 0.25 | 黑斑、软腐、坏死 |
   | `spot` | 邻域梯度突变密度 | 病斑数量与碎裂程度 |

3. 与 `common/disease-kb.js` 里每条病害的 `sign` 向量做**皮尔逊相关系数**，取 Top5；
4. `load`（病斑负荷）= `brown + dark + spot` 的加权和。`load < 0.07` 时判为「叶面干净」，**不硬凑病名**，直接返回健康。

`pseudoFeatures(seed)` 是兜底：某些机型取不到 canvas 时，用图片路径哈希生成稳定的伪特征，保证同一个图每次结果一致，不会出现「刷新一下病名就变了」。

### 2.3 知识库结构（`common/disease-kb.js`）

```
PLANTS    10 种   番茄 / 辣椒 / 黄瓜 / 茄子 / 白菜 / 水稻 / 柑橘 / 草莓 / 玉米 / 豆角
DISEASES  25 条   每种作物 2~3 条高发病害
GROW       8 条   缺氮 / 缺钾 / 缺铁 / 水害 / 光照不足 / 肥害 / 药害 / 冷害
```

单条病害字段：

```js
{
  id: 'tomato-early-blight',
  plant: 'tomato',
  name: '番茄早疫病',
  alias: '轮纹病',
  type: '真菌',                    // 真菌 / 细菌 / 病毒 / 虫害 / 生理
  severity: 3,                     // 1 轻 ~ 4 重
  sign: { yellow: .14, brown: .2, white: .04, dark: .07, spot: .5 },
  symptoms: ['……三条田间可观察的现象'],
  causes:   ['……四条成因'],
  plan:     { agri: [...], bio: [...], chem: [...] },   // 农业 / 生物 / 化学三档
  medicine: '苯醚甲环唑 10% 水分散粒剂 1500 倍',
  prevent:  ['……预防要点'],
  confuse:  ['tomato-late-blight'],   // 易混淆，结果页会提示怎么区分
  tip: '……一句田间经验'
}
```

**三档方案（`plan.agri / bio / chem`）是本模块的设计重点**：不是一上来就推农药，而是先给不打药的办法（整枝、控水、轮作），再给生物制剂，最后才是化学药并注明轮换。农户按自己的接受度选。

### 2.4 严重度

`severityOf()` 把知识库的基准严重度和本次的 `load`、置信度合成为四级：

| 等级 | 文案 | 建议 |
|---|---|---|
| 1 | 轻微 | 观察，先做农业措施 |
| 2 | 中等 | 生物制剂 + 局部处理 |
| 3 | 偏重 | 立即用药，控制蔓延 |
| 4 | 严重 | 拔除病株、清园，保其余地块 |

### 2.5 接入服务端模型

#### 候选模型（GitHub 实测可用）

| 仓库 | 模型 | 大小 | 类别 | 许可 | 说明 |
|---|---|---|---|---|---|
| `AbdelhamidKHELLADI/plants_disease_detection_lite` | MobileNetV3-Small + TFLite INT8 | ~1 MB | 38 | MIT | 体积最小，适合端侧/边缘部署，量化后精度损失小 |
| `Moztafaa/plant-diseases-model` | TFLite + Flask | ~9 MB | 38 | MIT | 已带 Flask `/predict`，返回 `{predicted_class, confidence}`，最快能跑起来 |
| `Pranav-Dwivedi/plant-disease-classifier` | MobileNetV2 + Temperature Scaling | ~14 MB | 38 + background | MIT | 带「背景/非叶片」类，能挡掉随手拍的乱图，置信度校准过 |

三个都是 PlantVillage 数据集训的 38 类，标签完全兼容，共用同一张 `CLASS_MAP`。**推荐组合**：先用 `Moztafaa/plant-diseases-model` 快速验证全链路，稳定后换 `plants_disease_detection_lite` 降本，最后视需要上带背景类的方案。

#### 接入步骤

1. 把模型服务部署到任意 HTTP 服务（Flask / FastAPI / 云函数都行），约定：

   ```
   POST {endpoint}
   Content-Type: multipart/form-data     字段名 file
   → { "predicted_class": "Tomato___Early_blight", "confidence": 0.93 }
   ```

2. 小程序启动时（`App.vue` 或 `main.js`）配置：

   ```js
   import { setDiagnoseConfig } from '@/api/diagnose.js'

   setDiagnoseConfig({
     endpoint: 'https://your-host/predict',
     token: 'Bearer xxxxx',        // 需要鉴权时
     minModelConfidence: 0.5       // 低于此值回落端侧
   })
   ```

3. 标签映射已在 `api/diagnose.js` 的 `CLASS_MAP` 里写好，键统一小写、空格与连字符转下划线，兼容各仓库的不同写法：

   ```js
   'tomato___early_blight' → 'tomato-early-blight'
   'corn___common_rust'    → 'corn-rust'
   'apple___healthy'       → 'healthy'
   ```

   新增病害时，**在 `disease-kb.js` 加条目 + 在 `CLASS_MAP` 加一行映射**，页面零改动。

4. 域名要加到小程序后台的 request / uploadFile 合法域名，本地调试时勾「不校验合法域名」。

#### 回落规则

```
模型返回         → 置信度 < minModelConfidence ? 用端侧 : 用模型
模型标签不在 CLASS_MAP → 用端侧
映射到 'healthy'  → 直接判健康，不再匹配
模型超时 / 报错   → 静默用端侧，不打断用户
```

### 2.6 结果数据结构

```js
{
  id, at, mode, provider,          // provider: 'local' | 'model'
  filePath,
  plant:   { key, name, emoji } | null,
  healthy: Boolean,
  disease: { id, name, type, confidence, fromModel, ...知识库全字段 } | null,
  alternatives: [{ id, name, confidence }],     // 易混淆的前两条
  severity: { level, text, tip },
  growth:  [{ id, name, type, symptoms, causes, plan, confidence }],  // 长势提醒 1~2 条
  feature: { yellow, brown, white, dark, spot, load },
  featureText: '黄化 18% / 褐变 22% / 病斑密集'
}
```

### 2.7 存储

| key | 内容 | 上限 |
|---|---|---|
| `nh_diagnose_v1` | 识别记录（`toRecord()` 压缩后的轻量结构，不含大图） | 24 条，超出丢最旧 |

## 三、专家问诊

### 3.1 两端角色

| 端 | 身份 | 入口 | 能做什么 |
|---|---|---|---|
| 农户端 | `farmer` | 首页「专家问诊」/ 诊断结果页「问专家」 | 提问、追问、评价、关闭 |
| 专家端 | `expert` | 工作台 → 问诊工单 | 接单、回复、查看统计 |

专家端靠 `store/expert.js` 的 `myExpertId` 区分——同一份数据，`myQuestions()` 取「我发出的」，`inboxQuestions()` 取「发给我的」。演示环境 `myExpertId = 'e1'`（李建国），所以同一个账号既能发问诊也能在工单池里看到自己名下待回复的。

### 3.2 数据结构

```js
question = {
  id, at, expertId,            // expertId 为空表示「不指定专家」
  crop,                        // 作物 key
  title, content,
  images: [path],
  status,                      // pending / answered / closed
  fromDiagnose: Boolean,       // 是否从识图结果转来
  messages: [
    { id, at, from, text, images }   // from: 'user' | 'expert'
  ],
  rating, ratedAt, closedAt
}
```

### 3.3 状态机

```
        addQuestion()
             │
             ▼
        ┌─────────┐  addMessage(from='expert')  ┌──────────┐
        │ pending │ ─────────────────────────► │ answered │
        │ 待回复  │ ◄───────────────────────── │  已回复  │
        └─────────┘  用户追问 addMessage('user') └──────────┘
             │                                     │
             └────────── closeQuestion() ──────────┘
                            ▼
                       ┌────────┐
                       │ closed │  已关闭（可评价，不可再追）
                       └────────┘
```

状态文案统一走 `qStatusText(s)` / `statusTone(s)`。**注意**：函数名带 `q` 前缀，是因为 `api/adopt.js` 里已经有一个 `statusText`，`api/index.js` 统一 `export *` 会撞名导致构建失败。

### 3.4 与识图的打通

`resultToQuestion(r)` 把诊断结果压成一段可直接发出去的话，预填到提问框：

```
作物：番茄
识图结果：番茄早疫病（置信度 78%）
严重度：偏重
图像特征：黄化 18% / 褐变 22% / 病斑密集
请帮我确认一下诊断，并给个用药方案。
```

农户在 `result.vue` 点「问专家」→ 带着这段话和原图进 `ask.vue`，少打一堆字。字段 `fromDiagnose: true` 会让专家端在会话顶部多显示一个「识图诊断」来源标记。

### 3.5 快捷模板

`ASK_TEMPLATES` 五个高频场景，点一下就把症状描述填进去，农户不用组织语言：

| key | 按钮 | 填进去的话 |
|---|---|---|
| `yellow` | 叶片发黄 | 叶片发黄，从下部老叶开始，叶脉还是绿的。 |
| `spot` | 叶子长斑 | 叶片上出现褐色斑点，有的带轮纹，边缘有黄圈。 |
| `wilt` | 整株萎蔫 | 白天萎蔫、早晚又恢复，反复几天了，挖出来根是褐色的。 |
| `fruit` | 果实烂 | 果实表面出现水渍状斑，慢慢软腐，上面长了一层霉。 |
| `bug` | 叶背有虫 | 叶子背面有很多小虫，叶片卷曲，还有黏黏的东西。 |

这几句的措辞是照着 `disease-kb.js` 的 `symptoms` 写的，专家一眼能对上号，也方便以后做自动预判。

### 3.6 存储

| key | 内容 |
|---|---|
| `nh_expert_v1` | 问诊单列表 + `myExpertId`，预置 3 条种子数据便于演示 |

|---|---|---|
| 模型推理 | `POST /diagnose` | multipart，返回 `predicted_class` + `confidence` |
| 病害知识库 | `GET /diseases?plant=` | 可先内置，改动少 |
| 识别记录 | `GET/POST /diagnose/records` | 需要按用户隔离 |
| 专家列表 | `GET /experts?crop=&online=` | 分页 |
| 问诊创建 | `POST /questions` | 带图片走 `uploadFile` |
| 问诊消息 | `GET /questions/:id/messages`、`POST /questions/:id/messages` | 建议长轮询或订阅消息 |
| 未读计数 | `GET /questions/unread` | 工作台角标 |
| 评价 | `POST /questions/:id/rate` | 影响专家评分 |

**订阅消息**：专家回复后给农户发一条「你的问诊有回复了」的小程序订阅消息，是这个功能能不能真用起来的关键，别漏。
