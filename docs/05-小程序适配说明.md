# 05 · 微信小程序适配说明

本目录是把 `E:\agriculture_app`（uni-app App/H5 工程）派生出的微信小程序版本。

## 一、工程结构

与 `uni_app_wms` 一致的 **HBuilderX 原生工程**，不走 CLI：

```
E:\agriculture_wxapp\
├── App.vue / main.js / manifest.json / pages.json   ← 全部在根目录
├── pages/ components/ api/ common/ mock/ store/ static/
├── docs/
└── unpackage/dist/dev/mp-weixin/                    ← 编译产物（开发者工具只认这个目录）
```

**没有** `package.json`、`node_modules`、`vite.config.js`、`src/`。

原因：HBuilderX 用 `getIsCli()` 判断工程类型，只要 `package.json` 与 `src/manifest.json` 同时存在就按 CLI 工程处理，
会去 `node_modules` 找编译器；原生结构才会用内置编译器。

## 二、微信开发者工具导入路径（最容易踩的坑）

**不要**把 `E:\agriculture_wxapp`（源码目录）导入开发者工具。
源码目录没有 `app.json`，导入必然报：

```
[app.json 文件内容错误] app.json: 在项目根目录未找到 app.json
```

正确做法：导入编译产物目录

```
E:\agriculture_wxapp\unpackage\dist\dev\mp-weixin
```

或者在 HBuilderX 里 `运行` → `运行到小程序模拟器` → `微信开发者工具`，它会自动编译并打开该目录。

### 千万不要把产物拷回根目录

把 `unpackage/dist/dev/mp-weixin/*` 复制到 `E:\agriculture_wxapp\` 会**覆盖掉全部源码**
（`App.vue`、`main.js`、`manifest.json`、`pages.json`、所有 `.vue` 页面），
换来的只是 `app.js` / `app.json` / `.wxml` 这些编译产物，源码无法从产物还原。

根目录也**不要**放 `project.config.json`：uni-app 编译时会把它原样复制到产物，
开发者工具就会一直把源码目录当成小程序工程，反复报找不到 `app.json`。
（当前已移除，产物里的配置由编译器自动生成。）

## 三、数据层：本地库代替云端

云端 BaaS 已下线（`xiangnonghui.app.workbuddy.host` 的 REST 接口返回 404「链接已失效」），
小程序端没有后端可用，因此改为本地数据模式。

- `common/local-db.js`：用 `uni storage` 复刻云端 SDK 的查询接口
  - `from(table).select(fields, opts).eq().in().order().range().limit().single().maybeSingle()`
  - `.insert() / .update() / .delete()`
  - 返回值形状 `{ data, count, error }`，且是 thenable（可直接 `await`）
  - 自动补 `id` / `created_at` / `updated_at` / `owner_id`
  - `user_follows` 特殊处理：归属字段是 `follower_id` 而不是 `owner_id`
- `common/cloud.js`：按平台分流，H5 走云 SDK，小程序/App 走本地库；
  导出 `IS_LOCAL_MODE`（小程序端为 `true`）

这样 `api/*.js` 一行都不用改，页面照常调用。

数据只存在本机 storage，卸载小程序即丢失，删掉开发者工具的「全部缓存」也会清空。

## 四、登录方式（重要）

小程序端没有后端，所以：

| 方式 | 实际情况 |
|---|---|
| 微信一键登录 | **拿不到 openid**。`wx.login` 的 `code` 必须在服务端用 appid + appsecret 换 openid，本地无法完成。现在点按钮会用本机标识直接建号进入，不依赖后端。 |
| 手机号登录 | **不会真的发短信**（需要短信服务商和签名备案）。点「获取验证码」后，6 位验证码**直接显示在页面黄色提示条里**，输入即可登录。 |

本地账号：

- 一键登录：`user_id = u_ + 本机标识`，同一台设备重复登录是同一个账号
- 手机号登录：`user_id = u_ + 手机号`

两套账号的本地数据互不相通，切换登录方式等于换了一个人。

要做成真实登录，必须补后端：

1. 微信一键登录：服务端调用 `https://api.weixin.qq.com/sns/jscode2session`，
   用 appid + appsecret + code 换 `openid`，再签发自己的 token
2. 手机号登录：接短信服务商（阿里云/腾讯云短信），服务端下发并校验验证码

在这之前，登录只能是本地演示。

## 五、用内置编译器手动编译（不需要登录 DCloud）

`publish` 命令要求登录 DCloud 账号，但直接调用 HBuilderX 自带的编译器可以出包：

```bash
cd "D:/HBuilderX/plugins/uniapp-cli-vite"
UNI_INPUT_DIR="E:/agriculture_wxapp" \
UNI_OUTPUT_DIR="E:/agriculture_wxapp/unpackage/dist/dev/mp-weixin" \
UNI_PLATFORM=mp-weixin \
node node_modules/@dcloudio/vite-plugin-uni/bin/uni.js build -p mp-weixin
```

关键点：**必须 cd 到编译器目录再执行**。CLI 会用 `process.cwd()` 覆盖 `UNI_CLI_CONTEXT`，
而编译器要读该目录的 `package.json` 来枚举 `@dcloudio/*` 平台插件（含 vue 编译能力）。
项目自身不需要 `package.json` 和 `node_modules`。

成功输出 `DONE  Build complete.`。

## 六、其它适配点

| 位置 | 处理 | 原因 |
|---|---|---|
| `common/utils.js` | `uni.switchTab` → `uni.reLaunch` | 本项目用自定义 `tab-bar` 组件，`pages.json` 里没有 `tabBar`，`switchTab` 在小程序端会失败 |
| `App.vue` | `<style lang="scss">` → `<style>` | HBuilderX 内置编译器不带 sass；原内容本就是纯 CSS |
| `uni.scss` | 已删除 | 无任何引用，留着会触发 sass 编译 |
| `manifest.json` | 只保留 `mp-weixin`，移除 `app-plus` / `h5` / `quickapp` / DCloud appid | 纯小程序工程 |
| `manifest.json → mp-weixin.appid` | `wx00025c1841c755b4` | 编译时写入产物 `project.config.json` |
